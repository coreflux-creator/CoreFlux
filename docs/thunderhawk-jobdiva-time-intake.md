# JobDiva time intake hardening

November 12, 2026 candidate. The preceding goal turn made progress by installing required person-document audit and physical-identity checks. This continuation revalidated clean tracked source at `a7b7cb46` and all eleven successful checks in run `43243638820`. Installed pilot runtime remains `b413c5bd`; this candidate is not installed and JobDiva time intake remains off in the pilot.

The earlier adapter accepted unrecognized hour types as regular billable time, cast malformed hours to numbers, created period/week records before full validation, could reopen a locked period, and advanced mapping payloads even when an approved time update changed no row. It did not retain a required source/entry receipt. The candidate validates explicit aliases, calendar dates, hours, supported categories and one-component rows before mutation. Missing, conflicting, withdrawn, oversized or unsupported source records are refused rather than reinterpreted.

Each accepted record uses a transaction pinned to the current operating company, JobDiva connection/account identity, configured source ownership, current People and placement directories, mapped placement, worker and work dates. Initial time remains a Core draft. A monthly processing period uses a separate seven-day staffing artifact. Daily capacity, original week/period locks, financial lineage, payroll reservations and retained historical payroll evidence are checked. Those financial checks reuse the existing source-correction guard and perform no provider writes.

Migration 195 adds retained encrypted source and resulting-entry receipts. Mapping, native time, weekly totals, artifact history, source history, receipt and required audit commit together. Exact replay returns the original receipt without changing timestamps or writing another audit. Draft source changes require the actual Core-owned fields to match the prior receipt. A source date/placement/worker change, changed submitted/approved time, competing Core edit, changed account/directory or legacy mapping without a receipt requires separate review. Existing provider IDs are never reassigned. Original provider approval assertions are retained as **unverified** and never become Core approval.

The existing outbound adapter is not replaced by this candidate; its unknown-category fallback is removed. Real source-shape/cohort acceptance, explicit legacy-link adoption, a reviewed protected-time correction screen, source-approval verification and outbound acknowledgement/reconciliation remain open. The dictionary retains the wider JobDiva time review gap and declares the new internal evidence fields without enabling any exchange. This is an incremental implementation toward the full integration, not a declaration of complete JobDiva time support.

Local checks pass: 41 strict input cases, 31 existing direction/wiring checks, 28 weekly-artifact checks and 161 time-field contract checks. New native MariaDB checks cover actual transactions, monthly-period/weekly-artifact separation, retained source approval assertions, stable IDs, original-key replay, unknown input, closed/locked periods, daily capacity, source-account/directory isolation, legacy-link refusal, competing edits, protected approval and required audit/history/receipt failures. Native CI and hosted installation/acceptance are pending. No real payroll, payments, financial postings, production cutover or Arabella change is authorized by this work.
