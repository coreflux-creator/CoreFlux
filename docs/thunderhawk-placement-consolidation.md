# Reviewed placement consolidation

This source work follows accepted historical identity readers `8afa5af9`. The full integration goal remains active. The merge service is not connected to the operator screen or deployed; source-owner adoption and remaining operational readers must be completed before the pilot can use it.

`modules/placements/lib/merge_review.php` replaces heuristic survivor selection with an exact survivor/retired pair, an explicit choice for each descriptive field, an exact retained JobDiva binding for future source ownership, confirmation that the survivor remains the current configuration, and confirmation that historical rows stay on their original identities. Different people cannot be consolidated by a name match. Existing aliases must be complete, foreign-workspace source bindings require ownership review, and in-flight or uncertain placement deliveries block consolidation.

The protected review reads current reviewer grants, independent directory policies, both placements, their permanent-number families, all retained provider mappings, relevant delivery evidence, custom values and physical placement-reference history. Every selected descriptive value becomes Core-owned. Approved rates, time, invoices, payment/payroll evidence, documents, schedules and commercial configuration remain on their original physical rows. Choosing the other current configuration means choosing the other placement as survivor; consolidation does not move or approve a rate snapshot.

Apply requires the unchanged review fingerprint, complete choices, an explicit confirmation, request ID and reason. It changes the survivor's selected descriptive values and their ownership, archives the selected duplicate, flattens its permanent-number family, and writes a mandatory audit receipt in one protected transaction. The receipt contains the chosen source binding, history fingerprints, exact choices and encrypted original placement rows. An exact retry recovers that receipt without repeating the operation or undoing later edits; changed intent, revoked access, changed directory or installation identity cannot reuse it.

This service records the future source-owner choice without rebinding or deleting any provider pair. The next implementation must make source writers consume that decision, replace the old automatic cleanup and expose the reviewed flow, including historical navigation. Existing provider IDs and the separate Arabella pilot remain unchanged. No production cutover, payroll, payment or financial posting is performed by this work.
