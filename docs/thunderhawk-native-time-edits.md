# Native time ownership and editing

Exact source `c7fa91cd` passed all eleven [CI jobs](https://github.com/coreflux-creator/CoreFlux/actions/runs/43528873414), including 46 required native time races and 45 required native time HTTP cases. [Pinned evidence](../deploy/thunderhawk-native-time-edits-preparation-20261113.json). This source has not been installed on the pilot.

Time entries, weekly headers, periods and time settings belong to the workspace where the work was recorded. Sharing a staffing, people or placement directory does not move those time facts into the parent company's books. The staffing timesheet API and library now use explicit original-workspace reads and writes; people and placements still resolve through their independently configured directories.

Single-entry save/delete, whole-week save and explicit reopen run inside one protected transaction. Directory policies, current placement identities, workers, headers, original entries, time periods and daily capacity are checked while their relevant database locks are retained. Header/artifact creation, reopened workflow state, edited entries, totals and required receipts commit or roll back together. Nested callers use savepoints. Each edit receipt retains the before and after facts; deletion retains the deleted row.

Only draft, pending-review and rejected entries are editable through these paths. Approved, superseded, extracted or imported Quanta entries keep their existing correction workflow. Reopening a submitted/rejected week changes only native pending/rejected siblings to draft; approved siblings keep their exact rows and approval evidence, and imported Quanta siblings retain their recorded review state. The reopen receipt records both original and resulting entries. Locked/closed periods refuse edits. Retired placement identities cannot be retargeted or erased through ordinary time editing, and an actual placement end date takes precedence over its planned end date.

The native session tests cover shared staffing catalogs, original child-workspace time, parent time isolation, existing self-versus-reviewer permissions, stale directory changes, invalid dates/placements/hours, mismatched headers, required-receipt failure, preservation of approved/superseded/imported time, locked periods, weekly rollback and per-entry partial results. Independent connections exercise committed and rolled-back approval, supersession, source binding, placement merge/archive, worker archive, period locking and directory changes; competing new entries cannot together exceed the daily 24-hour limit.

Exact-source CI acceptance is complete; the guarded pilot upgrade and hosted acceptance remain pending. It does not establish completion of the separate generic time API, submission/rejection/approval concurrency, rendered per-entry correction controls, CSV imports, AP/current-reference consumers or the full Thunderhawk round trip. Production, real payroll, payments, financial postings and the Arabella pilot remain outside this change.
