# Shared operating schedule editing

The shared schedule API now reviews the selected definition, its current placement and participant consumers, and any payroll bridge before accepting a change. A save requires the review token and `UPDATE_SHARED_SCHEDULE`. A newly linked consumer or changed reviewed value invalidates the review. An exact retry of values already applied returns unchanged success.

A successful edit updates the definition, each linked current placement summary, participant schedule ownership and the associated payroll calendar in one transaction. It records a placement audit for each affected placement and a required shared audit. Failure of the final audit rolls back the earlier updates and audits. Changing AP defaults reaches payees that inherit those defaults while preserving explicit participant and placement terms. Approved rate snapshots retain their historical content. Core operating schedule IDs, payroll cycle IDs and payroll schedule IDs are retained.

The edit uses parent-first locks, then the tenant, participants and definitions, to match native assignment ordering and prevent a new assignment entering an already-reviewed consumer set. Shared edits currently serialize placement writes across the affected workspace while the short transaction runs. They do not lock another workspace's placements. Corporate metadata participates in a binary-safe review token and is not returned in the public review.

Source-managed and standard frequency definitions cannot be repurposed through the native shared editor. A referenced schedule cannot be disabled until its current references are resolved. A payroll connection requires payroll-cycle management permission in addition to placement management. The native payroll cycle and pay-schedule update/delete paths cannot bypass the staffing impact review. Payroll pay-schedule reads and writes now enforce their module permissions.

Payroll and placement data owners must also match. A child workspace that shares its parent's placements but keeps payroll private cannot modify the parent's payroll calendar through its local payroll grant. When payroll is explicitly shared too, the reviewed edit and native payroll guards resolve the same authorized owner.

Generated payroll periods, watermarks, profiles and default payroll settings are included in impact review. A calendar with generated periods requires a replacement schedule for a changed cadence, anchor or offset. A rename preserves generated period values. An independently shared backing schedule/cohort is not silently changed through a single staffing definition. The existing create-and-assign service can establish a separate replacement; a future-dated bulk transition and operator screen for that transition are still required.
