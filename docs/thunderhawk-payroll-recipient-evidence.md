# Native payroll earning recipient evidence

## Behavior

Recorded payroll commissions and referral earnings previously resolved their recipient through the current economic participant and current account/employment matches each time payroll was recalculated. A later participant edit or reassigned sign-in account could therefore change the employment record receiving an existing earning.

New native payroll obligations now save an immutable recipient receipt in the same transaction as the earning. It retains the exact employment directory, employment ID and company payroll-profile ID, plus the original source, amount, currency, run and participant references. The final writer locks the placement, validates a draft run in the company, rechecks the approved recipient and refuses ambiguous employment. A failed receipt insert rolls back its earning. Recalculation uses the saved employment/profile IDs and checks their eligibility; it does not rematch the current participant or sign-in account.

Exact retries retain the original receipt and final source status. Conflicting amounts, run destinations, dates or statuses require a separate correction. Existing receipts also prevent source upserts from changing a recorded earning. One-time-item and commission replay paths validate the original receipt. Later participant changes and retirement do not rewrite it; disabling the original employment/profile causes a review error rather than selecting a replacement.

Migration 197 creates one empty evidence table. It does not adopt old earnings from current identity. An older payroll earning without a receipt requires original payroll evidence before adoption; no automatic backfill or historical-adoption UI is included. The isolated pilot contained no such legacy native payroll obligations at preflight, and the installer repeated that check before making changes. Worker-time reads continue to use the previously reviewed permanent person/employment link; this release concerns the separate economic-earning recipient path.
