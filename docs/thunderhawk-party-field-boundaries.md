# Company, client and vendor field boundaries

The previous goal turn installed person-profile boundaries. This continuation reverified all 347 runtime fingerprints and all 35,205 existing rows, then inspected the actual company/client/vendor APIs, directory helpers, JobDiva importers and PurePay customer packet.

The installed release defines the remaining native company, contact, address, relationship-role, client and vendor fields. CO company, CL bill-to profile and V payee identities stay distinct, with their existing directory owners and provider mappings. Company/party defaults do not rewrite approved placements, time or financial document history. Existing customer publication evidence is preserved. Unsupported receiving fields, private data and derived counters remain explicit instead of inheriting an imagined sync contract.

Inspection found a real vendor response defect: detail reads selected `v.*` but removed only tax ciphertext. Bank ciphertext and internal encryption metadata could still enter the response, and binary content could make JSON encoding fail. The new explicit public projection keeps canonical IDs, normal directory fields and masked suffixes, drops ciphertext, key metadata, opaque legacy remittance JSON and unknown future fields, and preserves the separate permission-gated full-tax reveal. Payment execution still reads its private server-side fields directly; no provider or financial action is added.

The company inspection also found unfinished integration behavior, not completed ownership control. Legacy JobDiva company/contact importers can overwrite native values and match contacts by company/email. Their fields are marked `legacy_inbound_conflict_review_required`; country/default behavior and stable contact matching remain explicit acceptance work. Native company document-reference validation and normal browser upload also remain open. A defined field disposition does not close those implementation gaps.

Local checks pass: 590 party-field assertions, 301 person-field assertions, 111 existing ownership assertions, 371 stable-number assertions and the vendor public-projection behavior check. Expanded native HTTP tests cover anonymous/missing-grant denial, normal AP reads with encrypted fixture data, masks and canonical IDs, private-field exclusion, restricted tax reveal, foreign-company denial and unchanged source rows. Runtime `4e62d6a6` passed all eleven jobs in [CI 43347950202](https://github.com/coreflux-creator/CoreFlux/actions/runs/43347950202) and is installed in the isolated Core pilot. The native login/API fixture passed 376 checks, including encrypted vendor responses and restricted tax reveal. Independent verification checked 350 runtime fingerprints and preserved all 35,205 rows across 378 tables, configuration, approved/current commission terms and retired test access. A read-only projection of all three existing pilot vendors passed; these three rows contain no encrypted values, so encrypted behavior is established separately by the native CI fixture. The installed inventory has 2,125 fields and 245 undecided dispositions, resolving 94. See [release evidence](../deploy/thunderhawk-party-fields-20261112.json). Production, provider systems, Arabella and financial execution are unchanged.

A further native vendor gap remains open: supplied company IDs are not checked against the independently configured Companies directory, and read joins assume the AP and Companies owners are identical. Shared/isolated directory validation and stable company linking are the next implementation work. The response projection above does not claim to fix that association.
