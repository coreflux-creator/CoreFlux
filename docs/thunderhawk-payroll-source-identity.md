# Native payroll source identity and currency

## Scope

This change closes a native Core consumption gap found while implementing the Thunderhawk commission contract. People already had reviewed permanent employment links, but native Time-to-payroll extraction and payroll recomputation still selected workers using mutable contacts or account matches. The economic-earnings query could multiply a commission across matching employees, omit unresolved sources, and add currencies together. Native overtime categories such as `OT_billable` were also counted as regular hours on this path.

Worker hours now use the saved person/employment link and the requesting company's enabled payroll profile. Account-only commission recipients must resolve uniquely; no contact matching is used. Unlinked source time remains unextracted with an operator explanation. Already-extracted time or economic obligations with missing, ambiguous, disabled or conflicting recipients raise a review error before payroll lines are replaced. Rate snapshots must belong to the source placement and retain approval. Canonical and legacy overtime labels use one shared classifier.

Shared People directories are resolved separately from company-owned payroll profiles. Explicitly extracted workers remain on the computation roster when their placement's routing differs from the profile's default cycle. A recipient included only for economic earnings continues to suppress regular salary/hours. People compensation/tax reads restore the caller's module scope even on failure.

The native payroll engine implements US payroll and has no foreign-currency calculation or conversion contract. Rate snapshots, one-time economic items, stored obligations and employment compensation must therefore explicitly use USD on this route. The source currency is preserved; this does not convert or reinterpret Puneet's INR 7,500 one-time commission. Separately denominated commission terms and their payout route remain unfinished.
