# JobDiva source-field refresh

Field refresh now reads the exact retained JobDiva assignment in its original workspace and resolves the current business-directory owner independently. It requires the same worker source identity and retained assignment link, uses that workspace's saved mirrors, and records the evidence before fetching missing related fields. Remote lookups run outside database transactions. Before saving, the service locks and rechecks current sharing, placement, worker, source-link, connection and joined-mirror evidence. A concurrent native edit, source change or loss of directory access rejects the stale save.

Returned roots, worker/job/company/contact IDs, exact Start contracts and financial detail must match the reviewed assignment. A cross-linked cached worker is rejected as well. Source snapshots, their content hashes, source-field indexes and the actor-attributed audit commit together. Required index or audit failure rolls back the operation. Source IDs, raw/prefixed pairs, internal IDs, source observation timestamps and native business rows are preserved. Enrichment does not activate a placement, edit a profile, claim native ownership, change rates or approve financial data.

Field-mapping administrators can use the same management permission as the existing mapping tools. Signed-out and read-only requests remain denied, GET cannot write, and changed company sharing blocks the request. Per-record errors are returned as failures rather than successful empty work. Summary counts distinguish committed snapshot changes from remote lookup attempts. Repeated maintenance can increment existing field-observation counters; it creates no duplicate business identities. A stale concurrent save cannot replace subsequently saved evidence.
