# Company merge source identities

This is preparation for the reviewed company merge workflow, not completion of that workflow. The legacy merge API and screen have not been replaced, and this runtime has not been installed in the pilot.

The source adapter preserves each original `external_entity_mappings` pair. A retired company can resolve to a current company only through its permanent `core_record_numbers` alias, in the currently configured Companies directory. Ordinary deletion does not create an alias. Missing, foreign, inconsistent or inactive alias targets are refused. Repeated merges use the flattened canonical number target; provider IDs and original CO numbers remain unchanged.

JobDiva company refreshes return the canonical relationship ID but keep secondary-source proposals on the original retired company. Neither that historical profile nor the survivor is overwritten. Roles follow the same rule. Configured custom fields retain typed proposals, including definition and mapping IDs; restricted fields and invalid values still fail. A failed mapped-field observation rolls back the source payload and all proposals. Semantic replay does not increase the ownership revision.

Assignment company, chain, referral and subcontract resolution, requisitions, contact parents, contact link review, graph identity binding and assignment field enrichment use this distinction. Assignment graph binding does not replace an existing company profile snapshot with sparse assignment data. Field enrichment routes proposals to the original source company rather than incorrectly attributing them to the survivor's primary provider identity. Native edits and the generic source-accept operation cannot resurrect or release source authority on a retired company.

## Required next implementation

Replace the old merge API and screen with a preview and explicit field/role choices. Bind apply to the current actor, workspace, directory policy, exact companies, source bindings, numbers, references and reviewed values. Require an atomic audit receipt, safe replay and stale-review rejection. Retain every provider binding and original source evidence; expose secondary source proposals from the surviving company with an explicit apply-once workflow that leaves the chosen fields Core-owned.

The live metadata-only inventory at 05:33:28 UTC found 18 numeric company-reference columns, plus two unrelated string ACH company identifiers. The numeric references are in accounting journal lines, AP 1099/bills/payments/vendors, billing invoices, company addresses/contacts/roles, people graph actor links, placements, client chain, corporate details, economic parties, referrals, staffing clients/jobs and treasury liability statement lines. The legacy merge omits several of these. The two ACH identifiers must not be treated as Core company IDs. Evidence is `output/company-merge-reference-inventory-20261113.json`.

The merge design must distinguish editable current references from immutable financial/source snapshots, preserve V/CL/provider identities, and account for independently shared AP and Companies directories. Lock and validate concurrent source/native writers; refuse inconsistent foreign references without partial changes. Generic mapping-list reads currently omit retired-company source aliases and use the directory owner rather than necessarily the source workspace; this also needs correction with permission tests. Retain original source custom values and document pointers as evidence, with explicit choices rather than silent replacement.

After those changes, prove the real reviewed merge through native HTTP, a signed-in hosted walkthrough and replay/conflict/isolation cases, then install only the verified complete candidate in the isolated pilot. Broader integration, real-source cohort, portal, document, time, payroll result and financial reconciliation requirements remain open. No production cutover, provider mutation, real payroll, payment, posting or Arabella change is authorized or performed here.
