# Commercial field ownership and destinations

The November 12 source review traces client-chain rules, referral fees, commissions, corporate payee details and commission projection metadata to their native validators, edit/review routes and ownership controls. The dictionary now defines each supported editor field's meaning, units, Core owner, write policy and remote boundary. The implementation preserves every previously recorded adapter mapping and leaves unknown future fields unreviewed.

The installed metadata-only inventory at 22:51 UTC contained 2,125 entries, including all three visible custom-field registries (empty). Comparing the candidate against that inventory changes 87 existing field descriptions/ownership decisions, resolves 71 previously undecided dispositions and 73 undecided owners, and leaves 372 dispositions unresolved. These counts are field decisions, not successful deliveries. The preflight separately verified 342 installed runtime fingerprints and all 35,040 original Core rows; no business record was changed by the inventory.

Core owns accepted commercial configuration. Authorized native rule edits claim the complete rule set and retain required audits; replacing it from saved JobDiva source needs a separate review. Corporate identity changes preserve company/vendor distinctions and require review of private tax records and documents. Existing JobDiva and Quanta vendor-reference mappings remain intact. Portal credentials, encryption metadata, corporate EIN data and private document references receive explicit restricted handling and no blanket remote destination.

The review keeps implementation gaps visible. Unconfigured commission-plan references and legacy corporate-name aliases are retained for review. A raw commission-rule receiver is not implemented in PurePay/PurePayroll. Independent commission currency, one-time/pay-period frequency and due month remain distinct from placement currency and schedule; native INR 7,500 / one time / August 2026 input stays exactly that, without conversion or an invented payment day. Existing native USD earnings and held provider staffing inputs are separate workflows. The dictionary grants no new provider, portal, payroll or payment permissions.

Local validation checks coverage against the actual native editor field lists, rejects private fields through generic input, preserves implemented mappings, retains unsupported receiver gaps, and exercises the real commission-input validator. Existing field-ownership, time-contract and record-number checks also pass.
